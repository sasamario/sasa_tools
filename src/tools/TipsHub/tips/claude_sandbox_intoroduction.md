## 1. サンドボックスとは

Claude Code のサンドボックスは、**カーネルレベルでファイルシステムとネットワークアクセスを制限する機能**です。各 OS の機能を活用して実装されており、信頼やプロンプトエンジニアリングではなく、技術的に強制的にセキュリティ境界を設けます。

### プラットフォーム別の実装方式

各 OS が提供しているセキュリティ機能が異なるため、実装方式も異なります

- **macOS**: 組み込みの Seatbelt フレームワーク（Apple が用意したセキュリティ機能）を使用
- **Linux/WSL2**: seccomp や namespace などの Linux カーネル機能を使用（bubblewrap がこれらをラップ）
- **Windows**: Windows 自体に同等の機能がないため、WSL2 ディストリビューション内で実行

## 2. 必要性（セキュリティリスク）

### Claude Code 特有のリスク
通常のコマンドラインと異なり、Claude Code は**自動でコマンドを実行**します。

```text
【通常の npm install】
$ npm install some-package  ← ユーザーが明示的に実行
  ↓
悪質なコードが走る
  ↓
リスク： 大規模
 
【Claude Code での npm install】
ユーザー：「このプロジェクトを改善して」
  ↓
Claude が自動で npm install を実行
  ↓
悪質なコードが走る
  ↓
リスク： 大規模（さらに、ユーザーが監視できていない可能性）
```

Claude Code はユーザーの明示的な操作なしに自動実行されるため、通常の CLI より注意が必要です。**だからこそ、サンドボックスで保護することが重要**です。

### サンドボックスなしの場合のリスク
`例：npm install で入れた1つの悪質なパッケージが、あなたの全ファイルにアクセス可能`

```text
npm install some-innocent-looking-package
  ↓
実は悪質なコードが含まれている
  ↓
以下を全てできてしまう：
├─ SSH キーの読み込み
├─ 環境変数の流出（API キー、クレデンシャル）
├─ シェル設定へのバックドア挿入
├─ ~/.bashrc などシステムファイルの改変
└─ 全ディレクトリへの無制限アクセス
```

**なぜこんなことができるのか？**
- npm で入れたパッケージはあなたのユーザー権限で実行される
- サンドボックスがないと、パッケージがあなたにアクセスできるファイルは全てアクセス可能
- 1つの悪質なパッケージだけで、複数の被害が連鎖的に発生
### サンドボックスがあった場合はどう安全になるのか

**同じく悪質なパッケージが入った場合の比較：**

```text
【サンドボックスなし】
npm install evil-package
  ↓
悪質なコード実行
  ↓
SSH キーを読み込み → ✅できてしまう
環境変数を盗む → ✅できてしまう
~/.bashrc を改変 → ✅できてしまう
被害： 🔴 大規模（アカウントが乗っ取られる可能性）
 
【サンドボックスあり】
npm install evil-package
  ↓
悪質なコード実行
  ↓
SSH キーを読み込み → ❌ OS がブロック
環境変数を盗む → ❌ OS がブロック
~/.bashrc を改変 → ❌ OS がブロック
プロジェクトフォルダ内のファイル改変 → ✅ 許可
被害： 🟡 軽微（プロジェクトファイルのみ影響）
→ git で復元すれば復旧できる
```

つまり
- サンドボックスがない = 悪質なパッケージが何でもできる
- サンドボックスがある = 悪質なパッケージでも、プロジェクトフォルダ内の操作だけに限定される
### サンドボックスの保護機能
 
| 項目 | サンドボックスなし | サンドボックスあり |
|------|----------------|---------------|
| ファイル書き込み | 全ディレクトリ可能 | ワーキングディレクトリのみ可能 |
| ファイル読み取り | 全ディレクトリ可能 | システム全体可能（除外ディレクトリ除く） |
| ネットワーク | 制限なし | ドメイン制限＋許可リクエスト |
| プロセス隔離 | なし | あり |

## 3. サンドボックス有効化
### 重要：デフォルトではサンドボックスは無効です
Claude Code を起動しても、**最初はサンドボックス機能は有効になっていません**。明示的に有効化する必要があります。

### 基本的な有効化手順

```bash
# ステップ1：Claude Code を起動
claude code

# ステップ2：Claude Code のセッション内で以下を実行
/sandbox

# ステップ3：メニューから選択
## 以下のようなメニューが表示されます
┌─────────────────────────┐
├─ ✅ with auto-allow
├─ ⚙️  with regular permissions
├─ ❌ no Sandbox
└─────────────────────────
```

### サンドボックスモードの説明
 
| モード | 説明 | 使用場面 |
|--------|------|---------|
| **with auto-allow** | サンドボックス内のコマンドは許可を求めずに実行 | 信頼できるプロジェクト・ローカル開発 |
| **with regular permissions** | 制限の多いコマンドは許可を求める | 初めてのプロジェクト・不確定な操作 |
| **no Sandbox** | サンドボックス機能を使わない | セキュリティ不要な環境のみ |
 
**推奨：** 最初は **with regular permissions** で試して、プロジェクトに慣れたら **with auto-allow** に切り替えるのが良いでしょう。
 
### プラットフォーム別初期化
 
**macOS**
```bash
# 1. Claude Code を起動
claude code
 
# 2. セッション内で有効化（何もインストール不要）
/sandbox
 
# 3. モードを選択
# Seatbelt フレームワークが組み込まれているため、そのまま使えます
```
 
**Linux/WSL2**
```bash
# 1. 必要なパッケージをインストール
sudo apt-get update
sudo apt-get install bubblewrap libseccomp-dev socat

# 2. Claude Code を起動
claude code

# 3. セッション内で有効化
/sandbox

# 4. モードを選択
```

**Windows（ネイティブ実行の場合）**
```bash
# 1. Claude Code を起動
claude code

# 2. セッション内で実行
/sandbox

# ⚠️ 注意：Windows ネイティブではサンドボックスは利用不可
# メッセージが表示される場合があります
```

**Windows（WSL2 の場合）**
```bash
# 1. WSL2 内で実行
wsl
cd /your/project

# 2. Claude Code を起動
claude code

# 3. セッション内で有効化
/sandbox
```
