# Network

## スロットリング（通信速度の制限）

ネットワーク不調・低速回線を擬似的に再現できる機能。実際の通信速度を落としてリクエストを送受信させることで、**ネットワーク起因の不具合を手元で再現・調査**するのに役立つ。

### 基本的な使い方

1. DevTools を開く（`F12` または `Cmd+Option+I`）
2. **Network** タブを選択
3. タブ上部のドロップダウン（デフォルトは `No throttling`）をクリック
4. プリセットを選択して適用

| プリセット | 用途 |
|---|---|
| No throttling | 制限なし（デフォルト） |
| Fast 4G | 高速モバイル回線の模倣 |
| Slow 4G | 低速モバイル回線の模倣 |
| 3G | 旧世代モバイル回線の模倣 |
| Offline | 完全にオフラインにする |

### カスタムプロファイルの作成

プリセット以外の条件（例：パケットロスが発生する不安定な回線）を再現したい場合は、カスタムプロファイルを作成できる。

1. ドロップダウンから **Custom... → Add...** を選択
2. 以下の項目を入力して保存

| 項目 | 内容 |
|---|---|
| Profile Name | プロファイルの名前（任意） |
| Download | ダウンロード速度（kb/s） |
| Upload | アップロード速度（kb/s） |
| Latency | レイテンシ（ms）。大きいほど応答が遅くなる |

作成したプロファイルはドロップダウンに追加され、次回以降も再利用できる。

### ローカル環境では適用されない

`localhost` へのアクセスは、OS の**ループバックインターフェース**を経由する。  
これはネットワークカードを一切通らない仮想的な経路であり、「自分自身への通信」として OS が処理するため、物理的な通信遅延や帯域制限が発生しない。

Chrome のスロットリングはブラウザが送受信するデータを意図的に遅延させる仕組みだが、**ループバック通信はこの制御対象外**になっている。  
結果として、`localhost` や `127.0.0.1` への通信は制限がかからず、どのプリセットを選んでも高速なままになる。

### ローカルでスロットリングを試したい場合

JS には `sleep` に相当する組み込み関数がないため、`Promise` と `setTimeout` を組み合わせて代替する。

```js
// ms ミリ秒後に resolve() を呼ぶ Promise を返す。await することで指定時間だけ処理を止められる。
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
```
`await sleep(2000)` のように使う。`async` 関数の中でのみ `await` が使えるので注意。
`resolve()`は非同期処理の結果が成功したことを伝えるための機能。


```js
const fetchData = async () => {
  await sleep(2000); // 2秒遅延してから処理を続ける
  const res = await fetch('/api/data');
  return res.json();
};
```
